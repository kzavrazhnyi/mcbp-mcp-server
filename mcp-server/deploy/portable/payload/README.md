# mcbp-ai MCP — портабельна поставка для Windows

Самодостатня тека: усередині вбудований Python і встановлений пакет `mcbp[http]`.
Нічого ставити в систему не треба — скопіюйте теку на потрібну машину і запустіть.

## Швидкий старт

1. Скопіюйте всю теку на цільову машину (наприклад у `C:\mcbp-mcp`).
2. Відкрийте `server.env` у Блокноті і впишіть адресу своєї бази BAS та обліковку.
3. Запустіть `start.cmd`.
4. Перевірте, що сервер живий: у браузері `http://127.0.0.1:8010/healthz` має відповісти `ok`.

Сам MCP-ендпоінт — `http://127.0.0.1:8010/mcp`. Саме цю адресу вписують у клієнта
(конектор MCP). Він відповідає лише на POST/GET/DELETE у межах MCP-сесії, тому просто
відкрити його в браузері не вийде — для перевірки живості є `/healthz`.

Зупинка сервера — `Ctrl+C` у вікні `start.cmd`.

## Що всередині

| Файл / тека | Призначення |

| `python\` | вбудований Python 3.11 з pip і встановленим `mcbp[http]` |

## Налаштування

Усе в `server.env`. Формат — `KEY=VALUE`, кодування UTF-8, `#` на початку рядка це
коментар. Значення може бути порожнім — саме так задається порожній пароль демо-бази.

Найважливіше:

- `ONEC_BASE_URL` — адреса HTTP-сервісу `MCBP_AI` **без** хвостового `/ai/v1`.
- `ONEC_USER` / `ONEC_PASSWORD` — обліковка BAS. Ключ `ONEC_PASSWORD` має бути присутній
  навіть із порожнім значенням, інакше сервер не стартує.
- `MCP_HTTP_HOST` — `127.0.0.1` означає «лише з цієї машини». Для доступу по мережі
  поставте `0.0.0.0`.
- `MCP_HTTP_PORT` — типово `8010`. Якщо порт зайнятий, змініть його тут.
- `MCP_ALLOW_WRITE` — `0` дає 10 інструментів читання; `1` додає три інструменти запису.

### Дві обліковки, не одна

Якщо клієнт надсилає заголовок `Authorization: Basic <base64 користувач:пароль>`, кожен
виклик інструмента виконується під **його** обліковкою BAS. Обліковка з `server.env`
працює лише для запитів без цього заголовка. Тому тримайте в `server.env` обліковку з
мінімальними правами: це те, чим стає анонімний клієнт.

## Оновлення

Запустіть `update.cmd`. Він підтягне свіжу версію `mcbp[http]` з TestPyPI і надрукує
встановлені версії. Файл `server.env` при цьому не змінюється.

## HTTPS

Поставка вміє https, але сертифікат ви створюєте самі — це одна дія руками.

1. Відкрийте PowerShell **від імені адміністратора** (обов'язково: скрипт вносить
   кореневий сертифікат у сховище машини).
2. Виконайте в теці поставки:
   ```
   powershell -ExecutionPolicy Bypass -File .\make-cert.ps1
   ```
   Для доступу по мережі вкажіть реальні ім'я та адресу машини:
   ```
   powershell -ExecutionPolicy Bypass -File .\make-cert.ps1 -DnsName mcbp.local -IPAddress 192.168.1.50
   ```
3. Розкоментуйте в `server.env` два останні рядки:
   ```
   MCP_HTTP_SSL_CERTFILE=certs\mcbp-mcp.crt.pem
   MCP_HTTP_SSL_KEYFILE=certs\mcbp-mcp.key.pem
   ```
4. Перезапустіть `start.cmd`. Адреса стане `https://<ім'я>:8010/mcp`.

Щоб інша машина довіряла цьому серверу, скопіюйте на неї `certs\mcbp-mcp.cer` і внесіть
у «Довірені кореневі центри сертифікації» локального комп'ютера.

**Чому це важливо.** Облікові дані BAS ідуть у заголовку `Authorization: Basic` при
**кожному** запиті. По http вони перетинають мережу відкритим текстом. Поки сервер
слухає лише `127.0.0.1`, це не має значення; щойно ви поставили `MCP_HTTP_HOST=0.0.0.0` —
вмикайте https.

## Якщо не запускається

| Симптом | Причина |
|---|---|
| `помилка в server.env: ...` | пропущений або порожній обов'язковий ключ; перевірте `ONEC_PASSWORD` — він має бути присутній |
| `пакет mcbp[http] не встановлений` | поставка неповна або зіпсована — розпакуйте архів заново, тоді `update.cmd` |
| вікно закривається одразу | запускайте `start.cmd` подвійним кліком — воно лишається відкритим з `pause`; текст помилки буде вище |
| `address already in use` | порт зайнятий іншим процесом — змініть `MCP_HTTP_PORT` |
| клієнт не бачить інструментів | перевірте `/healthz`, тоді адресу з `/mcp` на кінці |
| немає інструментів запису | `MCP_ALLOW_WRITE=0` — це типовий стан, поставте `1` і перезапустіть |
